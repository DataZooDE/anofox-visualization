|---|---|

## How it was set up

One DuckDB process with three small tables (`sales`, `targets`, and `access`, which says who may see which region) and two dashboards in a folder:

- **Login:** an [auth proxy](../security/) in front of the server sends a shared secret and the user's name. In the recording, the browser sends those headers itself, so switching the header switches the viewer.
- **Row policy:** `sales` and `targets` get the same rule, `region IN (SELECT region FROM access WHERE viewer = getvariable('__claim_user'))`. The server rewrites every query with it — the panels, the inputs' options, the saves and the exports.
- **Write-back:** `options.writeback` declares the `targets` table, its columns and who may save. The `::SAVE` button sends the `::FORM`'s values; the server checks them against the declared types and the policy, appends them to its change log and stamps the row with the writer's name.

The script that starts the server and records the video is [`scripts/record-walkthrough.mjs`](https://github.com/DataZooDE/anofox-visualization/blob/master/scripts/record-walkthrough.mjs); its header says how to re-record it.
